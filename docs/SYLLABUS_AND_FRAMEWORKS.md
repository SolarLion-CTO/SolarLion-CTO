## 2. Twenty key concepts for strategic AI decision-making (as listed)

| # | Concept | Decision-making application |
|---|---|---|
| 1 | Mintzberg 5Ps | Use multiple lenses to shape AI strategy (plan, position, pattern, perspective, ploy) |
| 2 | Porter's generic strategies | Choose cost leadership, differentiation or focus strategy for AI initiatives |
| 3 | Theory of Constraints | Identify and address the real constraint limiting AI performance or scale |
| 4 | Strategy quality tests | Test strategy for consistency, consonance, advantage and feasibility |
| 5 | Pipeline vs platform | Decide whether AI is a workflow (pipeline) or a reusable enterprise capability (platform) |
| 6 | Open vs closed architecture | Choose between provider-managed (closed) and open-weight / self-hosted (open) |
| 7 | Investment matrix | Prioritise AI initiatives based on value, risk and investment |
| 8 | Risk process | Identify, assess, intervene and govern AI risks continuously |
| 9 | Stage-gate | Use gates to control progression from idea → MVP → production → scale |
| 10 | Crossing the chasm | Navigate AI adoption from innovators to the mainstream enterprise market |
| 11 | Diffusion factors | Evaluate relative advantage, compatibility, complexity, trialability and observability |
| 12 | Network effects | Leverage data, users, agents and ecosystem advantages to create compounding value |
| 13 | Modularity × coordination | Decide between platform, ecosystem or vertically integrated architecture |
| 14 | McKinsey 7S | Align seven dimensions: strategy, structure, systems, skills, staff, style and shared values |
| 15 | Kotter 8 steps | Drive change through an 8-step enterprise transformation approach |
| 16 | Lewin 3 stages | Manage change in three stages: unfreeze → change → refreeze |
| 17 | Theory E vs Theory O | Balance economic transformation (Theory E) with organisational capability (Theory O) |
| 18 | Business Model Canvas | Define AI value proposition, customers, channels, key partners and revenue model |
| 19 | XaaS | Consume or deliver AI, platform and model capabilities as a service |
| 20 | Winner-take-all | Assess whether network / ecosystem economics favour concentration and scale leadership |

### What to remove or consolidate
- **Don't treat every framework equally.**
  - **Eisenhower Matrix** is useful personally but too tactical for the main CTO library.
  - **RICE** is excellent in product environments but doesn't need to be a primary enterprise CTO framework.
  - **Bow-Tie** is useful for specific risk analysis, but **Three Lines + enterprise risk assessment** matters more at CTO level.
- **Duplicates:**
  - **Three Horizons** and the McKinsey Horizon Model are the same family; learn them once.
  - **ADKAR** and Prosci ADKAR are the same framework.

### The 15 to master deeply
To sit in an executive meeting and **apply a framework to a business problem**, concentrate on:

**PESTLE → Five Forces → SWOT → Porter Value Chain → Ansoff → Three Horizons → Business Model Canvas → Balanced Scorecard → OKRs → Stage-Gate → McKinsey 7S → Kotter → ADKAR → Cynefin → Three Lines**

Keep the rest as a **toolbox**.

### When to use which framework (the decision guide)
| Executive question | Framework(s) |
|---|---|
| What's happening outside? | PESTLE / Five Forces |
| Where are we? | SWOT / VRIO |
| Where should we compete? | Porter / Ansoff / Blue Ocean |
| Where is the value? | Value Chain / Business Model Canvas |
| What should we invest in? | Three Horizons / NPV / ROI |
| What should we prioritise? | Value vs Effort / Stage-Gate |
| How should we organise? | 7S / Operating Model |
| How do we transform people? | Kotter / ADKAR |
| How do we execute? | Balanced Scorecard / OKRs |
| How do we decide under complexity? | Cynefin / RAPID |
| How do we govern risk? | Three Lines |

> You don't need 100 frameworks. You need to choose and apply the right one when a CEO, CFO, COO or business leader brings you a problem.

## 8. M8 LEAN: chosen plan (7 Oct 2026)

**"Lean" = the focused option.** It is not the Lean Startup framework.
- Build **only** the frameworks that directly serve a team member's BP1 problem **and** produce a metric worth tracking from old state to target state.
- Every other framework stays in the reference library (sections 2 and 6) and on a light Frameworks page. It is not built as a screen.

**Filter (all three must hold):**
1. It answers the owner's BP1 problem.
2. It gives a trackable measure, or a decision the owner actually makes.
3. It runs on the existing simulated data.
